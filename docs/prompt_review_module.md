# 任務：獨立模組/頁面邏輯獨立沙盒審查（Sandboxed Code Review）

請針對以下目標進行**純粹的內部邏輯審查**：
- <目標模組/頁面/路由>

## 審查核心限制

1. **隔離外部依賴（Isolated Sandboxing）**：
   請完全假設所有引用的其他模組、底層套件（Pacakges）、路由參數（Route Params）以及 API 請求的回傳結果**皆為 100% 正確且符合預期**。不要花時間質疑或驗證外部依賴的正確性。
2. **專注內部狀態與流程**：
   你唯一需要審查的，是該目標內部的「邏輯、狀態機變化、副作用（Effects）觸發時機、事件處理（Event Handlers）以及條件渲染（Conditional Rendering）」本身是否存在 Bug。
3. **拒絕外部文件對比**：
   不需比對任何外部遷移文件、規格書或記憶中的歷史版本。一切判斷「純粹以當前代碼現狀」的程式碼邏輯進行靜態分析。

## 輸出要求

請將你的完整分析與審查結果，**必定（MUST）**直接寫入到 `<目標路徑>` 這個檔案中，寫入內容需包含：

1. **結構簡述**：
   請用 ASCII 方塊字元（如 ├、─、└）繪製結構關係圖，範圍「僅限」該模組本身內部。
2. **內部 Bug 審查**：
   條列出內部邏輯（如 Race Conditions、記憶體洩漏、未處理的內部異常、錯誤的狀態更新）的具體 Bug。**【絕對禁止】寫出任何修復代碼、修復步驟或解決方法，僅指出問題點。**
